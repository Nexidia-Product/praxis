Section 1 · Overview

Introduction

Praxis is a web application for tracking, managing and prioritizing innovation projects, tasks and submitted ideas for a single team. It replaces a spreadsheet workflow with roadmap views, role-based access control, a public idea portal, an audit trail, health and resource analytics, a velocity dashboard, PowerPoint export and optional AI assistance. It is single-tenant: one organization, no separate workspaces.

1.2Who this guide is for

Read it if you hold the Admin role, or if a non-Admin role has been granted one or more administrative permissions (Section 3).

1.3How the application is built

Front end and server

A Next.js application. Pages render server-side and call internal service modules for all reads and writes.

Database and identity

Supabase (PostgreSQL) stores all data; Supabase Auth owns identity. The application profile (name, role, active flag, preferences) lives in a users table joined to the auth identity.

Hosting

Vercel. A daily Vercel Cron job drives the notification sweep (Section 12).

AI

Optional features call AWS Bedrock, controlled by an environment flag and per-feature model selection (Section 18).

Email

Invites, recovery and notifications go through Resend when configured; otherwise the content is logged.

Section 2 · Access

Authentication & access

2.1Identity model

Supabase Auth owns identity. Users sign in with an email address and password; Praxis never sees a plaintext password. Each identity is matched to an application profile carrying the display name, role, active flag and notification preferences. A deactivated account is treated as not signed in: the user is locked out on their next request while their history is kept.

2.2Sessions

  • Sessions are cookie-based. Middleware refreshes the session on every request so short-lived access tokens renew transparently.
  • Signing out clears the session cookies. Session lifetime otherwise follows Supabase Auth's token settings.

2.3Signing in and recovering a password

How to: Sign in
  1. Go to the application URL. If you are not signed in, you land on the login page.
  2. Enter your address in "Email" and your password in "Password".
  3. Click "Sign in". You are taken to the home page.
How to: Reset your own password
  1. On the login page, click "Forgot password?".
  2. Enter your address in "Email" and click "Send reset link".
  3. You see a generic confirmation. Check your inbox; the link expires in one hour.
  4. Open the link, enter a new password in "New password" and "Confirm password" (at least 12 characters, with three of: lowercase, uppercase, digit, special character), and click "Update password".
  5. You return to the login page to sign in with the new password.

New users join by invitation, not self-registration (Section 4). An invited user follows their link to a "Set your password" page, chooses a password and is signed in.

2.4Why email links use an interstitial page

Invite and recovery links carry a single-use token. Corporate email security (such as Microsoft Defender Safe Links) often fetches a link before the person clicks it, which would burn the token. To prevent that, the authentication callback returns a small page that submits a form to complete verification. Prefetchers follow links but do not submit forms, so the token survives until the person clicks.

If you customize Supabase email templatesKeep the callback URL format intact: the token passed as query parameters to the callback route.
Section 3 · Access

Roles & permissions

3.1The four roles

Every user holds exactly one role. What a role can do is set entirely by the permissions mapped to it, not by its name.

Admin

Full control. Always has every permission; this cannot be edited, so an Admin cannot be locked out.

Project Lead

Manages projects, tasks and the idea pipeline, can export the roadmap and see all resources. No Admin console by default.

Team Member

Works on projects and tasks (view, create and edit tasks; view projects) and views the roadmap and velocity.

Viewer

Read-only access to projects, tasks, ideas, the roadmap and the velocity dashboard.

3.2The permission catalog

A permission is the unit of access enforced throughout the app; each protected page and action checks a specific key. The full list is in Appendix A.

Projects · 6Tasks · 6Ideas · 3Roadmap · 2Insights · 4Administration · 14

Each admin surface is gated separately, so you can delegate a narrow slice of administration, such as task templates, by granting just that permission. Admin permissions only help alongside "Access the Admin section", which reveals the Admin group in navigation.

3.3Default role-to-permission mapping

RoleDefaults
Project LeadView, create and edit projects; view, create, edit, delete and move tasks; view, review and convert ideas; view and export the roadmap; view velocity; view resources and all resources.

3.4Editing roles & permissions

The mapping is data, so you can change who can do what without a software change. The editor is a matrix: permissions are rows grouped by category, roles are columns, and the Admin column is locked.

How to: Change what a role can do
  1. Under Admin, open "Resource management", then the "Roles & permissions" tab.
  2. Click the checkbox at the permission row and role column you want to change.
  3. Repeat for other pairs. Edits stay pending until you save.
  4. Click "Save changes". Use "Discard changes" to abandon edits, or "Reset to defaults" to return every non-Admin role to its seeded defaults (confirm in the dialog, then still Save).
Check navigationIf you grant an admin permission without "Access the Admin section", the page will not appear in that role's navigation. A banner warns you.

3.5How access is enforced

  • Signed-in or not is enforced globally. A few public routes need no session: login, forgot and reset password, invite acceptance, the public idea-submission portal and its API, and the auth callback.
  • Every protected page and action checks a specific permission. A signed-in user without it is redirected to a styled "403, not authorized" page showing their role; API calls return 403.

Section 5 · Core records

Projects

A project is the central record in Praxis. Each has an auto-assigned identifier in the form YYYY-NNN (year of creation plus a sequence number, such as 2026-001).

5.1Project fields

Identity
Name, description and a definition of done.
Classification
Application/product, project type, program, track, priority, stage and status.
Visualization
A visualization type (Data Only, Function Update, New Visualization, New Page, New Cognigy Build or None) and a visualization lead, shown in the quick view under the project lead.
Alignment
A primary objective, optional secondary objectives, the use case the project belongs to, the use-case outcomes it supports, and the NiCE products it aligns to.
Value
Free-text supports and benefits, plus the project's own outcomes.
People
A project lead (required), additional resources (registered users or free text), primary stakeholders and a per-resource allocation percentage.
Dates
Target application deployment date, target executable deployment date, and a start date. The start date is set automatically the first time a project leaves Not Started or Pending Assignment for an active status, unless already set.
Roadmap bucket
A free-text grouping used by the Now, Next, Later board. New projects default to "Unplaced".
Health
A computed Red, Yellow or Green score with a rolling history (Section 11).
AI
An AI complexity score and time estimate (Section 18), when AI is enabled.
Custom fields
Any administrator-defined fields (Section 14) appear on every project.
Links
Document links, internal dependencies and external dependencies.
Key capability
A flag and an optional committed quarter (Section 10).

5.2Status, track, stage and priority

Status, priority, program and track can be extended by administrators (Section 14). Stages are defined per track in code.

Status

Not Started, Pending Assignment, In Planning, In Progress, Blocked, On Hold, Delayed, Completed, Canceled. Pending Assignment sits between Not Started and In Planning and counts as open work.

Track

Tracks A to I. A project's track decides which stages it can be in (Appendix B).

Stage

Every track starts with Qualification and Prioritization and delivers at Productization, with its own stages in between. Replaced the earlier "phase" field. Changing a stage by hand needs the change-stage permission; stages otherwise advance as a stage's tasks are completed.

Program

Innovation, Complaints, UI Maintenance. New projects default to Innovation.

Priority

Critical, High, Medium, Low. Administrator-added priorities carry a rank.

5.3Working with projects

How to: Create a new project
  1. In the sidebar, click "Projects".
  2. Click "+ New project" (top right of the toolbar). The "New project" form opens.
  3. Fill in the form. "Name" and "Application/Product" are required. The form also offers description, definition of done, type, program, track, priority, status, stage, visualization type, project lead, visualization lead, objectives, use case outcomes, supports, benefits, outcomes, dates, stakeholders, additional resources and allocations, and (when available) "Apply task template", "Depends on", document links, external dependencies and any custom fields.
  4. Click "Create project". The modal closes and the project appears in the table.
How to: Edit a project
  1. On the Projects page, click the project's row to open its quick-view panel.
  2. Click "Edit project". The form opens with the same fields as create.
  3. Make your changes and click "Save changes".
How to: Change a project's status and record a note
  1. Open the project's quick-view panel.
  2. Open the "Status" tab.
  3. Choose the new status. Optionally type an explanation in the "Summary" note field.
  4. Click "Update status", or "Add note" to attach a note without changing the status. The change appears in the history list with timestamp and author.
How to: Add a dependency, an external dependency or a document link
  1. Open the project form (create or edit).
  2. Internal dependency: in "Depends on", pick an upstream project and set its type, "Blocks Start" or "Blocks Stage" (for "Blocks Stage", also pick the required stage). Cycles are rejected.
  3. External dependency: in "External dependencies", fill the "Title" (and optionally owner, URL, target date, description; status defaults to "Open") and click "Add dependency".
  4. Document link: in "Document & repository links", paste a URL (the link type is auto-detected), optionally add a label, and click "Add".
  5. Click "Save changes" (or "Create project") to persist.

5.4Dependencies, links and templates

  • Internal dependencies: "Blocks Start" (the upstream must finish before this starts) and "Blocks Stage" (the upstream must reach a specified stage). Cycles are detected and rejected.
  • External dependencies track work outside Praxis with a label, owner, optional link, status (Open, In Progress, Resolved) and optional target date. They feed the health score's upstream-risk consideration.
  • Document links are labeled links to GitHub, Confluence, SharePoint, network drives, Figma, Miro, Jira and generic resources. Most are stored as references. A link to a GitHub Markdown file is also fetched when AI is enabled, to ground the PRFAQ (Section 18.2).
  • Task templates applied at creation create the template's tasks on the new project with their dependencies preserved (Section 13).
Section 6 · Core records

Tasks

Tasks belong to a project and have their own auto-assigned identifiers. A task is the unit of trackable work. Its project is fixed at creation unless it is explicitly moved.

6.1Task fields and statuses

  • Fields: name, detailed description, status, priority, stage, a responsible owner (required) plus additional assignees, a target (due) date, an hour estimate, a "blocked" flag with optional blocker detail, comments with history, document links and task-to-task dependencies.
  • A task's stage must be one of the stages for its project's track (Appendix B).
Not StartedAwaiting DependencyIn ProgressBlockedDelayedOn HoldUnder ReviewCompleteCanceled

Task statuses are not administrator-extensible: the auto-unblock behavior and the health score rely on them.

6.2Task dependencies and auto-unblock

Tasks can depend on other tasks with the four standard relationship types (Finish-to-Start, Start-to-Start, Finish-to-Finish, Start-to-Finish). Praxis automates Finish-to-Start:

  • When a not-started task gains a Finish-to-Start predecessor, its status becomes "Awaiting Dependency". Removing the last such predecessor returns it to "Not Started".
  • When a task is marked Complete, every downstream task waiting on it is checked. If all of that task's Finish-to-Start predecessors are now complete, it is released back to "Not Started". An explicit status set by a user always wins.

6.3Working with tasks

How to: Add a task
  1. In the sidebar, click "Tasks", then "+ New task" (top right). You can also start from a template with "+ From template".
  2. In the "New task" form, choose the "Project" (required; only open projects are listed) and enter the "Task name" (required).
  3. Set the stage, status and priority, and optionally the responsible person, target date, estimate, additional assignees and comments.
  4. If the task is blocked, tick "This task is blocked" and use the "Blocked by" options ("Another task", "Another project" or "Other") plus the blocker details.
  5. Click "Create task".
How to: Mark a task complete
  1. On the Tasks page, find the task's row.
  2. In the "Actions" column, click the green check. The status changes to "Complete" immediately.
  3. Alternatively, open the task, set "Status" to "Complete" on the "Details" tab, and click "Save changes".
How to: Edit a task
  1. On the Tasks page, click the task's row to open the "Edit task" form.
  2. Use the "Details" tab to change fields, "Comments" to read the history and "Dependencies" to manage predecessor links.
  3. Click "Save changes".
How to: Move a task to another project
  1. Open the task (click its row on the Tasks page).
  2. On the "Details" tab, use the "Project" field: choose the destination project (only open projects are listed) and click "Move". Health scores on both projects are recalculated and the move is audited.
  3. Without the move permission, the project field is read-only.
How to: Use the My tasks list and checklist
  1. In the sidebar, click "My tasks". It shows tasks you are responsible for or assigned to.
  2. Switch between "List" (a filterable, groupable table) and "Checklist" (a personal, reorderable list of open tasks) with the buttons at the top.
  3. In Checklist mode, drag tasks by the grip handle into your preferred order; it saves automatically. Tick a task's checkbox to complete it.
Section 7 · Core records

Ideas & the public submission portal

Ideas are lightweight proposals that can be triaged and then promoted into projects, or merged into existing ones. They enter through a public portal and are worked in an internal review queue (sidebar: Insights, Ideas).

7.1Idea lifecycle

NewUnder ReviewApprovedRejectedConverted

New, Under Review, Approved, Converted, with Rejected as an off-ramp (an idea can be reopened from Rejected). Converted is terminal.

7.2Quality of Life and Bug / Defect flags

Both flags work the same way. A submitter can set either at submission, and a reviewer can set or clear either on the review page until the idea is Converted. A flagged idea shows a badge in the review list ("QoL" or "Bug") and in the idea header. Use them to separate fixes and small tweaks from new feature requests when you triage.

7.3Submitting, reviewing, converting and merging

How to: Submit an idea through the public portal
  1. Go to the public portal at /submit. No sign-in is required; share the link with stakeholders.
  2. Fill in "Your name" (required) and optionally "Email (optional)", used to send an update when the idea is reviewed.
  3. Enter the "Idea title" and "Description" (both required) and choose an "Urgency" (Low, Medium, High or Critical).
  4. Optionally set "Requested target date", "Key stakeholders" and "Attachments" (up to five files, 50 MB combined).
  5. Optionally tick "Quality of Life" (a minor usability tweak, not a new feature) or "Bug / Defect" (something not working as intended).
  6. Click "Submit idea". A confirmation shows a reference ID.
How to: Review an idea
  1. Open Insights, "Ideas". Use the filter buttons ("Open (New + Under Review)", "All", "New", "Under Review", "Approved", "Rejected", "Converted") to scope the list.
  2. Click "Review" on an idea's row to open it.
  3. Move it through review with "Mark under review", "Approve" or "Reject".
  4. Capture internal notes in "Reviewer notes" (never shown to the public) and click "Save notes". Download attachments with "Download".
How to: Check an idea for overlap with existing work
  1. Open the idea.
  2. In the "Overlap check" section, click "Run overlap check" (or "Re-run check"). It shows likely duplicate or related projects and ideas.
  3. With AI enabled the result is model-generated; otherwise a keyword heuristic is used. Either way the result is saved on the idea for other reviewers.
How to: Convert an idea into a project
  1. Open the idea and click "Convert to project" (requires the convert-ideas permission).
  2. Review the pre-filled fields and adjust as needed.
  3. Click "Create project & mark Converted". You are taken to the new project, and the idea is marked Converted and linked to it.
How to: Merge an idea into an existing project
  1. Open the idea and choose "Merge into project" (also needs the convert-ideas permission).
  2. Search for and select the target project. Completed and canceled projects are not listed.
  3. Review the pre-filled task (name and description come from the idea; priority is mapped from urgency). Choose the task's stage and enter an hour estimate, both required.
  4. Click "Create task & mark Converted". The task is created on that project and assigned to the project's lead, and the idea is marked Converted with a link back to the project. No new project is created.

Section 10 · Insights

Key capabilities

The Key Capabilities dashboard highlights the strategic projects the team is committing to, grouped by the quarter each is slotted for. Viewing needs only project access; designating capabilities and assigning quarters requires the "manage key capabilities" permission. At most two capabilities may be slotted per quarter.

  • Each card shows identity and health, a task-progress strip (open, past due, blocked, done) and an "x / x tasks complete" indicator with a percentage. Canceled tasks are excluded from that math.
  • Beneath the progress indicator, each card shows the project's most recent status note (Section 5.3). Cards with no note show a blank placeholder.
How to: Designate a key capability and slot it into a quarter
  1. Open the Key Capabilities dashboard (sidebar: Insights, "Key capabilities").
  2. In the "Add a key capability:" row, open "Select a project…", choose an un-flagged project and click "Add".
  3. On the project's card, use the quarter dropdown to commit it to a quarter. A quarter that already holds two capabilities will not accept a third.
  4. To remove the designation, click "Remove" on the card.
Section 11 · System

Health scoring

Every project carries an automatically computed health score plus a rolling history used to draw a small trend sparkline. The score is recomputed when a project's status changes and when its tasks change.

11.1How the score is determined

Red
  • Status is Blocked
  • Target date passed and the project is not closed
  • Blocked-or-overdue task share at or above the Red threshold
  • A hard upstream dependency is blocked
Yellow
  • Blocked-or-overdue share at or above the Yellow threshold
  • Target date near while a meaningful share of tasks is still open
  • A meaningful share of open tasks is due soon
  • No task activity for a configured number of days
  • An upstream dependency is at risk
Green

The default when none of the above applies. Completed and Canceled projects are treated as Green. Canceled tasks are excluded from task-share calculations.

11.2Thresholds and recalculation

  • Thresholds are set in Admin, Configuration, Health thresholds (Section 14.1). Red must exceed Yellow.
  • Changes apply to a project the next time it is recalculated. Use "Recalculate now" on the Health thresholds page to apply them to every project immediately.
  • History keeps one point per calendar day over a rolling window and is kept after a project closes. A degradation (Green to Yellow, or Yellow to Red) raises a notification; recoveries do not.

Notifications

Praxis delivers notifications in-app and, optionally, by email.

12.1Delivery and preferences

  • Each user chooses, per type, whether to receive it in-app only or by email and in-app, and may enable a daily digest.
  • Administrators set the organization-wide defaults in application settings. These are the fallback when a user has not set their own.
  • Idea Status Changed notifications go by email to the idea's submitter (submitters have no account).
  • A task created by merging an idea into a project is assigned to the project's lead, who receives the usual Task Assigned notification.
How to: Set your personal notification preferences
  1. Open your profile's Notifications page (Profile, Notifications).
  2. For each type, choose "In-app only" or "Email + in-app".
  3. Optionally tick "Daily digest mode" to receive one summary email per day instead of per-event emails.
  4. Click "Save preferences".

12.2The daily sweep

A scheduled job runs once a day (07:00 UTC via Vercel Cron) in four idempotent phases: notify on tasks due soon, notify on overdue tasks, send digests to users who opted in, and purge old read notifications. Running it more than once a day produces no duplicates.

How to: Run the notification sweep on demand
  1. Open Admin, "Notifications" (permission: run notifications sweep).
  2. Click "Run sweep now".
  3. Read the per-phase counts: "Due-soon notified", "Overdue notified", "Digests sent", "Old read purged", "Health-recalc projects" and "Duration". Running again right away gives zeros, because each phase de-duplicates against entries written earlier the same day.
Section 13 · System

Task templates

Task templates (Admin, Templates; permission: manage task templates) are reusable, ordered task lists that prefill a new project. When applied, each template task becomes a real task with a fresh identifier, and the within-template dependencies are rewritten to the new tasks. A template task's stage must belong to the tracks the template targets. If a template task has no default owner, the created task is assigned to the project's lead.

How to: Create a task template
  1. Open Admin, "Templates" and click "+ New" (left pane).
  2. Enter a "Template name" and tick every applicable track under "Tracks". Each task's stage options are the stages of the checked tracks.
  3. Under "Tasks", click "+ Add task" for each task and set its name, priority, stage, optional "Hours" estimate and optional description. Reorder tasks with the up and down controls.
  4. To link tasks within the template, use "+ Add dependency" on a task and pick a predecessor and a type (FS, SS, FF or SF).
  5. Click "Create template" (or "Save changes" when editing an existing one).

  1. Open Admin, Configuration, "Custom fields".
  2. Click "+ Add field" and set the "Label", the "Key" (lowercase letters, digits and underscores, starting with a letter) and the "Type" (Text, Number, Date, Yes / no or Single-select). Tick "Required" if needed; for Single-select, fill the comma-separated "Options".
  3. Click "Save changes".

How to: Add a project value (status, priority, application, program or track)
  1. Open Admin, Configuration, "Project values" and pick the "Status", "Priority", "Application / Product", "Program" or "Track" tab. Built-in values are shown but locked. The "Stage" tab is view-only: stages are defined per track in code, so ask engineering to add stages for a track that has none yet.
  2. In the add form, enter the "Label" and an "ID" (auto-derived, editable, must be unique). For Status set "Open" and "Terminal"; for Priority set "Rank". Click "Add".
  3. Click "Save changes". To retire a value later, "Archive" it (hidden from new dropdowns, kept on records that use it). "Delete" is only allowed for values never used. Treat the ID as permanent once in use.
How to: Manage outcome values
  1. Open Admin, Configuration, "Outcomes".
  2. Add or remove entries in the two lists that back the product and type dropdowns on project outcomes.
  3. Save. Both lists save together.
How to: Rename the portfolio quadrant labels
  1. Open Admin, Configuration, "Portfolio quadrants".
  2. Edit the four labels: "Quick Win", "Major Bet", "Fill-In" and "Deprioritize" (each up to 60 characters).
  3. Click "Save" (or "Reset to defaults"). Renaming does not move any project; quadrant membership is computed from priority and complexity.
How to: Set health thresholds and apply them now
  1. Open Admin, Configuration, "Health thresholds".
  2. Set the Yellow and Red blocked-or-overdue percentages (Red must be greater than Yellow) and the Yellow-only triggers (inactivity days, target-date proximity, open-task percentage, due-soon task percentage).
  3. Click "Save thresholds".
  4. Click "Recalculate now" to apply the new thresholds across every project immediately. Otherwise they apply as each project is next recalculated.
How to: Choose AI models per feature
  1. Open Admin, Configuration, "AI" (this tab appears only when AI is enabled in the environment).
  2. For each feature ("Complexity / time estimate", "Priority recommendation" and "Idea overlap"), pick a model. Each option is tagged with its routing scope. If the model list cannot load, paste a model id into the text box instead.
  3. Click "Save" (or "Reset to defaults").

14.2Resource management workspace

Holds people and access settings: Users (Section 4), Roles & permissions (Section 3.4) and Resource thresholds. The Users tab also controls program access: for each non-Admin user, the program control opens a popover with an "All programs" toggle and a checklist of specific programs; when more than one is checked you also choose a Primary. Click "Apply" to save. Admins are never restricted by program.

How to: Tune resource thresholds
  1. Open Admin, Resource management, "Resource thresholds".
  2. Adjust the sections: "Default allocation"; "Workload weights" (per assignment, open task, past-due task and bottleneck task, plus complexity and priority multipliers); "Workload bucket thresholds"; "Performance weights"; and "Performance score thresholds" (Yellow minimum below Green minimum, plus the look-back window in days).
  3. Click "Save thresholds". The Resources page reflects the new values on next render.

The application reads it defensively, so a record missing a newer field still loads with sensible defaults.

14.5Use cases

Admin, Use cases (permission: manage use cases). Top-level groupings tied to organizational objectives. Each has a name, description, a primary objective, optional secondary objectives, the NiCE products it aligns to, the outcomes it is meant to achieve, and its member projects. A project belongs to at most one use case, and its quick view shows it. Projects pick which of their use case's outcomes they support on the project form.

How to: Create a use case
  1. Open Admin, "Use cases" and click "+ New use case".
  2. Enter the name and description, choose the primary objective and any secondary objectives, and select aligned NiCE products.
  3. Add the outcomes the use case should achieve.
  4. Search for and add member projects. A project can belong to only one use case.
  5. Save.
How to: Export the use cases to Markdown
  1. Open Admin, "Use cases".
  2. Click "Export Markdown". A file named use-cases-YYYY-MM-DD.md downloads.
  3. The file has one section per use case: description, objectives, NiCE products, outcomes and a table of member projects with ID, name, status, stage and lead.

14.6NiCE products

Admin, NiCE products (permission: manage NiCE products). Add a product, rename or re-describe it, and deprecate or restore it. There is no delete: deprecating hides a product from new selections while existing use case and project alignments keep it.

Section 15 · Administration

Audit log

An append-only record of who changed what (Admin, Audit log; permission: view audit log). Entries are never edited or deleted.

  • Each entry records when it occurred, the actor (or "System" for automated changes), the entity type (Project, Task, Idea, User, Decision, Template or Settings) and its label, the action and a short summary such as "Status: In Progress to Blocked".
  • Actions include create, update, delete, status change, convert, merge, invite, deactivate, activate, role change and password reset.
  • Auditing is best-effort and never blocks the underlying operation, so read the log as a strong record of activity rather than a transactional guarantee.
How to: Find activity in the audit log
  1. Open Admin, "Audit log".
  2. Narrow the list with the "Entity", "Action" and "Actor" dropdowns (the actor list includes "System").
  3. Type in the "Search" box to match the entity name or summary. Click "Refresh" to reload, or "Clear filters" to reset. Results are newest first.

Section 18 · Operations

AI advisor

Four optional features, all gated by the AI_ENABLED environment flag. When it is off, the feature buttons and the Publish tab are hidden, the endpoints decline to run, and idea overlap falls back to its keyword heuristic.

Complexity & time estimate

Suggests a project's complexity and a rough time estimate from its description.

Priority recommendation

Reasons across the open-project list and proposes a ranking for review. Nothing is applied automatically.

Idea overlap

Compares a submitted idea against existing projects and ideas to surface likely duplicates (Section 7.3).

Document generation

Drafts a PRFAQ for a project from its structured data, which you edit and approve (Section 18.2).

How to: Generate an AI complexity and time estimate for a project
  1. Open a project's create or edit form (AI must be enabled, and you need create or edit permission).
  2. Below the description, click "Generate AI estimate" (or "Regenerate AI estimate"). A description of at least about 20 characters is required.
  3. The suggested complexity and time estimate appear in an "AI suggestion" banner and fill the form's fields. They persist when you save the project.
How to: Run an AI priority review
  1. On the Projects page, click "AI priority review" (visible when AI is enabled and you can create projects).
  2. In the "AI Priority Review" panel, click "Run review".
  3. Read the recommended ranking and per-project rationale. The output is advisory. Click a project to open it and adjust manually. Use "Re-run review" to refresh.
How to: Generate, edit and approve a PRFAQ for a project
  1. Open the project's quick-view panel and select the "Publish" tab (it appears only when AI is enabled).
  2. Click "Generate PRFAQ" (or "Generate another PRFAQ"). The button is disabled with a hint until the project has both a description and a target date. Drafting runs section by section and can take up to a minute.
  3. The new draft is added to the list and shown inline. Use "Copy" to copy its Markdown, or "Edit" to revise the text in place and then "Save".
  4. When the draft is ready, click "Approve" and confirm in the dialog. Earlier drafts are kept in the list.
  5. Publishing directly to Confluence is not yet wired; the approved draft is stored on the project and can be copied out.

18.1Models and credentials

  • An administrator chooses each feature's model on Admin, Configuration, AI (Section 14.1), from the live list of models the account can invoke. By convention the high-volume estimate uses a fast, economical model and the reasoning-heavy features use a stronger one.
  • The features call AWS Bedrock using long-lived IAM-user access keys. These replaced an earlier interactive SSO approach that could not refresh in the hosting environment, and they do not expire.
  • Some Bedrock inference profiles route across regions and can be blocked by an organization's region policy. The model picker labels each option with its routing scope.
  • Whether AI is active depends on AI_ENABLED and valid AWS credentials. Treat enabling AI as a deliberate decision (cost and data handling).

18.2Document generation and grounding

Driven by authored "skills": reusable prompt bundles (instructions, a product profile, a section outline and an input specification) stored in the database. The built-in PRFAQ skill is published by the "seed document skills" script (Section 17.1). Generating a document requires the edit-projects permission. The generator writes "To be determined" where a section has no supporting input, and draws on:

  • Project fields: name, description, application/product, definition of done, primary stakeholders, and the start and target dates.
  • Structured data: the project's outcomes, its tasks, the latest key finding on each task, its decision log and the originating idea.
  • Linked GitHub Markdown documents (Section 5.4): up to five per generation, each capped in size. Any that cannot be reached are skipped so generation still succeeds. Private repositories need GITHUB_TOKEN (Section 16).
